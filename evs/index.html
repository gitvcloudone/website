1 What is Amazon EVS?

Amazon Elastic VMware Service (Amazon EVS) is a native AWS service that deploys and runs VMware Cloud Foundation (VCF) directly inside your own Amazon VPC on dedicated EC2 bare-metal instances. There is no shared infrastructure — you get the entire physical host, with full root access to every VMware component.

EVS is self-managed. AWS looks after the bare-metal hosts and their firmware, the VPC networking and the EVS service itself. You install, patch and upgrade VCF, or have an AWS Partner such as Kyndryl, DXC, Accenture, CDW or Presidio run it for you. You bring your own VCF subscription from Broadcom; AWS bills for the EC2 hosts, a pair of VPC Route Server endpoints and the EVS control plane, plus FSx for ONTAP or Windows Server licensing if you use them.

Support works two ways. AWS Support covers the whole stack, VCF included, so you can always start there. If you have an active VCF subscription, you can also open VCF software cases directly with Broadcom.

Key differentiator: Unlike VMware Cloud on AWS (VMC), Amazon EVS runs inside your own VPC with no AWS-managed intermediate layer. You own the VCF lifecycle — patches, upgrades, and Day 2 operations are managed by you or an AWS Partner.

Core value propositions

🔄 Migration continuity

Migrate workloads without changing IP addresses, retooling staff, or rewriting runbooks. Same vSphere and NSX tools you use today.

🎛 Full architectural control

Root access to ESXi, vCenter, NSX Manager, and SDDC Manager. Supports third-party solutions and custom configurations.

☁ 200+ AWS services

Direct access to native AWS services — S3, RDS, SageMaker, EKS, Lambda, Direct Connect — without data movement.

⚖ Flexible management

Self-managed, or an AWS Partner runs VCF for you. Hosts on demand or on 1- or 3-year terms.

2 Architecture

The VCF stack on AWS

How the stack gets built depends on the VCF version:

  • VCF 5.2: EVS deploys the whole stack when you call CreateEnvironment: hosts, networking, vCenter, NSX, vSAN and SDDC Manager.
  • VCF 9.0 and 9.1: EVS provisions the bare-metal hosts running ESX 9 and the VLANs in your VPC. You then install VCF with Broadcom’s VCF Installer, the same way as on-premises, or let the EVS Deployment Orchestrator do the whole build from one CloudFormation stack in about 4 to 7 hours.

Network architecture & VLANs

EVS automatically provisions dedicated VLANs for all VMware traffic inside the VPC. The VPC Route Server exchanges BGP routes between the NSX Tier-0 Edge nodes and the VPC route table, eliminating static route management entirely.

EVS Network Topology — VPC VLANs & BGP Routing Architecture Diagram
BGP routes from NSX Tier-0 Edge nodes propagate automatically to the VPC route table via the Route Server. No static routes required.

Shared responsibility model

AWS manages

  • Bare-metal hosts (EC2 i4i, i7i, r7i) and their firmware
  • AWS global network and VPC infrastructure
  • Support for the whole stack, VCF included
  • Physical data center security
  • EVS control plane (CreateEnvironment API)
  • Hardware failure and replacement

Customer / Partner manages

  • VCF installation (VCF 9), patches, upgrades, Day 2 ops
  • VM workloads, guest OS, application security
  • NSX network policies and micro-segmentation
  • VCF subscription from Broadcom (optional direct Broadcom support)
  • IAM roles and VPC access controls
  • Backup, DR configuration, data protection
  • Regulatory and compliance requirements

3 Use Cases

EVS supports every stage of the cloud journey — from burst capacity and DR to full data center migration and modern application platforms.

Cloud Extension & Data Center Expansion

Extend on-premises VMware infrastructure to AWS without re-architecting workloads. Ideal for seasonal demand spikes, data center consolidation mandates, and capacity expansion. HCX live migration moves VMs with no downtime and no IP address changes.

Disaster Recovery

Use EVS as a recovery site, from a cold standby up to a warm cluster sized for critical workloads. VMware Live Recovery with vSphere Replication gives about a five-minute RPO and automates failover; FSx for ONTAP SnapMirror and Veeam are other options. NSX Federation keeps segments and firewall rules in place at both sites. AWS walks through the patterns in Disaster Recovery for VMware Workloads on Amazon EVS.

Rapid Cloud Migration & Legacy Retirement

Migrate VMware workloads to AWS in days, not months — without changing IP addresses, retraining teams, or rewriting applications. HCX bulk migration handles large VM fleets. After migration, incrementally refactor applications to consume native AWS services.

VCF as a Service (CapEx → OpEx)

Shift VMware infrastructure from capital expenditure to a consumption model. Hosts run on demand or on 1- or 3-year terms; AWS’s example puts i4i.metal at $10.98 an hour on demand and $5.08 an hour on a 3-year Instance Savings Plan in US East (Ohio). Windows Server can be licensed through EVS at $0.046 per vCPU-hour for VMs without license portability.

AI / Analytics & Modern App Platform

Keep data gravity on EVS while reaching native AWS AI/ML services (SageMaker, Bedrock) without data movement. VMware Kubernetes Service (VKS) runs containers natively alongside VMs, and VCF 9.1 memory tiering lets memory-heavy clusters run up to twice the VMs per host when active memory stays within DRAM.

4 Regional Availability

Getting started

Before running CreateEnvironment, AWS requires a specific set of VPC prerequisites to be in place. The vCloudOne prereq guide covers all 10 steps for the VCF 5.x flow, and the Terraform kit automates the AWS side in under 5 minutes. For VCF 9, most of the same AWS prerequisites apply; the EVS Deployment Orchestrator builds them and VCF together. To size an environment, try the EVS sizer.

Next step: Use the EVS Prerequisite Guide to set up your VPC, Route 53, DHCP, Route Server, and IAM resources — then run the Prereq Validator to confirm your environment is ready before calling CreateEnvironment.
