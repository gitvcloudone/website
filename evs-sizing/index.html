Sizing policy

Every cluster gets its own HA spare host(s). Minimum hosts per cluster are set automatically: management (or the shared cluster) 4 for HA profiles, 3 for Simple on vSAN, 2 on r7i; workload clusters 3 on vSAN (6 for manual RAID-6), 2 on r7i. No memory overcommit. Past the per-instance limit, the calculator adds EVS instances.

Sources and assumptions

  • Host types and VCF versions: AWS EVS User Guide, "Supported VCF versions and instance types" (r7i added Nov 2026; diskless types need external principal storage). EC2 instance specifications for cores and memory.
  • Hosts per instance: 32 (AWS, May 2026; service quota increase needed above the default).
  • Management resources: Broadcom VCF 9.1 "VCF Fleet Sizing Models" (first and additional instance totals per profile). Minimum hosts: VCF 9.x docs – Simple 2 (external) or 3 (vSAN); HA 4 (NSX Manager anti-affinity).
  • Memory tiering: AWS "Increase your cluster density with Memory Tiering in Amazon EVS" – default tier 1:1, drives leave vSAN, keep active memory under ~50% of DRAM.
  • Licensing: Broadcom VCF SPD – per-core, 16-core minimum per CPU. vSAN capacity is covered by the 1 TiB per core included with VCF: every EVS host type's raw NVMe is below its core entitlement.
  • On i-type hosts the local drives are always vSAN ESA (principal storage) minus memory-tier drives; FSxN is a supplemental datastore for a share of workload storage, and VCF management stays on vSAN. r7i uses FSxN for everything.
  • vSAN usable = raw × (1 − reserve) × compression ÷ protection factor per cluster. Auto policy: RAID-6 4+2 at 6+ hosts, RAID-5 2+1 at 3–5 (both 1.5); manual RAID-5 adaptive 4+1 = 1.25 at 6+; RAID-1 = 2. Spare hosts' drives aren't counted toward capacity. Workload is spread evenly across instances. Growth is one uplift for the contract term. Data last verified 23 Nov 2026.
