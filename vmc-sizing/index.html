SDDC design

Sized like VMC HA: workloads run on all hosts with no spare host, because VMC's auto-remediation replaces a failed host; stretched clusters are sized so either AZ can run everything. Clusters hold 2–16 hosts (stretched: in pairs). Clusters per SDDC: Auto fills each cluster to the max hosts in order and opens a new SDDC past VMC's 20 clusters or 300 hosts; a number spreads each SDDC's hosts evenly over that many clusters (extra hosts go to Cluster-1, Cluster-2, … in order) and opens a new SDDC once they're all full. Set SDDCs to split a large estate on purpose (e.g. one SDDC per AZ, or to spread north-south traffic across more NSX Edges); the workload is divided evenly and each SDDC carries its own management appliances.

Cloud Manager + one Interconnect (8 vCPU, 6 GB) + Network Extension (8 vCPU, 3 GB each; up to 8 networks per appliance; HA doubles them).
SRM appliance (light below 1,000 VMs) + vSphere Replication appliance + 1 replication server per extra 400 VMs. Replicas and failover compute are workload: add them as a group.

Sizing policy

Storage

Guest used = space used inside the VMs (RVTools vPartition); allocated = provisioned disk size (vDisk). Space efficiency ratio is vSAN compression only: VMC i4i/i7i don't dedupe. Free-space reserve keeps vSAN below 75% used (VMC slack; Elastic DRS adds hosts at 80%).

Sources and assumptions

  • Host types: i4i.metal (64 cores, 1,024 GiB, 8 × 3.75 TB NVMe) and i7i.metal-24xl (48 cores, 768 GiB, 6 × 3.75 TB) per Broadcom VMC docs and the i7i announcement (Apr 2026). i7ie.metal-24xl isn't offered on VMC yet: EC2 specification (48 cores, 768 GiB, 8 × 7.5 TB).
  • vSAN: new single-AZ SDDCs deploy on ESA (every drive is capacity); stretched clusters deploy on OSA (two drives per host for cache). i4i raw: 27.28 TiB ESA, 20.46 TiB OSA. Compression is on by default on both (no deduplication).
  • Limits: 2–16 hosts per cluster; 10 clusters per SDDC by default, 20 on request; 300 hosts per SDDC. Stretched clusters grow in pairs; 6+ hosts for the 99.99% SLA. Management CIDR is an output: the smallest range for each SDDC's hosts (/23 = 27 hosts, 22 stretched; /20 = 251, 246; /16 = SDDC maximum), or the next size up when within 20% of that range's limit, since it can't be changed after deployment.
  • Management: vCenter, NSX Managers and NSX Edges run in Cluster-1's Mgmt-ResourcePool with full reservations – Medium 34 vCPU / 116 GB, Large 68 vCPU / 240 GB (vCPU counted at the CPU ratio, RAM 1:1). Large is recommended above 30 hosts or 3,000 VMs and needs 3+ hosts in Cluster-1 (6+ stretched). Management storage defaults to the 11.12 TB management reservation in the VMC validated design (editable).
  • vSAN policy follows the VMC Managed Storage Policy: single-AZ RAID-1 at 2 hosts (mirrored across both hosts with a VMware-managed witness), RAID-5 2+1 (ESA) or RAID-1 (OSA) at 3–5, RAID-6 4+2 at 6+; stretched: dual site mirroring, adding local RAID-1 at 6+ hosts. Usable = raw × (1 − reserve) × compression ÷ policy factor, on all hosts in the cluster. VMC keeps 25% slack; Elastic DRS adds hosts at 80% used.
  • Management-only Cluster-1: a fixed host count (default 4, no extra HA host on top), raised only if the management load or the Large-appliance minimum needs more. Management vCPU is counted at the workload CPU ratio and RAM 1:1 (reservations are a GHz/GB pool, not a core per vCPU). Add-ons (per SDDC, Cluster-1): HCX Cloud Manager 4 vCPU / 12 GB / 64 GB (MON scale-up 8 / 24; large migration 16 / 48), Interconnect 8 / 6 GB, Network Extension 8 / 3 GB each (HA doubles; WAN Optimization retired Jan 2026). VMware Live Recovery: SRM 2 / 8 GB (light, under 1,000 VMs) or 4 / 12 GB, vSphere Replication 4 / 12 GB, plus one server (2 / 1 GB) per additional 400 replications. Multi-Edge: Large appliances and 2 Large edges (8 / 32 GB) per extra pair. NSX Advanced Firewall: Layer 7 App ID, FQDN filtering and Identity Firewall are included with VMC (since Feb 2024); Distributed IDS/IPS is a paid vDefend add-on, subscribed per core, with no appliances: 2 GB RAM per host is deducted; its CPU (up to 5 cores per host, in proportion to inspected traffic) isn't deducted because it uses the headroom the CPU ratio already leaves.
  • Utilization: peak CPU/RAM % per group replaces the ratios for that group; RVTools snapshot values (vCPU "Overall", vMemory "Active"/"Consumed") are shown for reference only. Large VMs: flagged when vCPU exceeds a host's threads (or physical cores, as a warning) or vRAM exceeds a host's usable RAM.
  • HA: VMC manages vSphere HA (percentage-based admission control, which applies to reservations) and auto-remediation adds a replacement host when one fails, so single-AZ clusters have no spare host: the CPU ratio and RAM are applied across all hosts. Stretched clusters are 2 × (each AZ holds the full workload). Memory tiering is a what-if using VCF 9 rules. Workload is spread evenly across SDDCs and clusters. Growth is one uplift for the contract term. Data last verified 23 Nov 2026.
