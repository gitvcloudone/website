This is the big one for Amazon EVS this year. You can now run VCF 9.0 and 9.1 in every Region where EVS is available.

**What changed in the model.** With VCF 5.2, EVS deployed the whole stack for you: hosts, networking, vCenter, NSX, vSAN and SDDC Manager. With VCF 9, the work is split. EVS provisions the bare-metal hosts running ESX 9, puts them in your VPC and connects them to the VLANs that form the VCF underlay. You then run Broadcom's VCF Installer and deploy VCF with the same workflow you'd use on-premises. Once the management appliances are up, you create an EVS connector so EVS can see the environment, report license use and enable Windows licensing.

**Why it's built this way.** Separating infrastructure from software means EVS runs standard VCF 9, deployed the standard way. The skills, runbooks and Broadcom documentation you already use apply as-is, and new VCF releases don't have to wait for EVS to change its deployment automation.

**Licensing.** You can deploy without license keys and run in evaluation mode, which helps for proofs of concept. Beyond that, you need VCF subscription coverage for the cores you run.

**What it unlocks.** VCF 9 brings memory tiering, VCF Operations and the rest of the 9.x platform to AWS.

The catch is that the VCF install is now your job. Have the VCF Installer, depot access and your subscription sorted before the hosts are up, because host billing starts when they come online. If you'd rather not do it by hand, the EVS Deployment Orchestrator automates the whole thing.
