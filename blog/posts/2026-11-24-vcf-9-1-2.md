Broadcom shipped VCF 9.1.2 today. Most of it is about getting AI and Kubernetes platforms running faster, plus two features moving from tech preview to GA.

**Quickstarts.** Some background: Supervisor is the Kubernetes control plane built into vSphere, and VKS (vSphere Kubernetes Service) uses it to create Kubernetes clusters for application teams. Turning it all on used to mean several separate workflows for networking, load balancing, Supervisor and the first cluster.
- **AI infrastructure quickstart:** one vCenter plugin configures the cluster, enables Supervisor and builds a VKS cluster, ready for AI workloads.
- **VKS quickstart:** gives you a production-ready Supervisor and VKS cluster, plus a test environment with the common add-ons and a UI to browse it.

**Chained VKr upgrades.** A VKr (VKS release) is the Kubernetes version a cluster runs. Kubernetes only supports upgrading one minor version at a time, so getting from an old version to a current one means several hops. Now you pick the target version and VCF plans the path, choosing the latest stable patch at each step and keeping add-ons in sync.

**GitOps service (GA).** Argo CD built into VCF. GitOps means the desired state of your apps and clusters lives in a Git repo, and Argo CD keeps the running environment matching it. Teams can create their own Argo CD instances from VCF Automation, with access through your existing identity provider via OIDC.

**vSAN object storage (GA).** S3-compatible object storage served from vSAN, with encryption, role-based access and multi-tenancy, provisioned self-service through VCF Automation or YAML.

The object storage is the one I'd pay attention to even if AI isn't on your roadmap. Backup software, log platforms and cloud-native apps increasingly expect an S3 endpoint. Having one inside VCF means you don't need a separate object store on-prem for them.
