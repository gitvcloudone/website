VCF 9.0.2 is mostly a fix release, but two changes in vCenter 9.0.2 remove common causes of trouble.

**Certificates renew themselves.** vCenter and ESX use TLS certificates that the built-in VMware Certificate Authority (VMCA) issues. When they expire, things break: hosts disconnect, logins fail, and it usually happens at an awkward time. From 9.0.2, vCenter's machine SSL certificate is extended by two years once it's within five days of expiring. ESX host certificates are extended by five years once they're within ten days, on hosts that support renewal without disruption. This only works in VMCA certificate mode. If you switched to custom certificates, it won't happen, and you'll need to set the mode back to "vmca" to get it.

**Supervisor backup is on by default.** Supervisor is the Kubernetes control plane built into vSphere. Its data is now backed up alongside the vCenter file-based backup by default, so restoring vCenter doesn't leave Supervisor broken.

The release also fixes several login problems, including one caused by the 90-day OAuth credential rotation in VCF SSO, and vpxd crashes when automation makes parallel API calls. If you're on 9.0.0 or 9.0.1, plan for 9.0.2. If you use custom certificates, the auto-renewal won't help you, so keep tracking expiry dates.
