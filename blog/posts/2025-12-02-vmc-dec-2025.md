Broadcom's December roundup for VMware Cloud on AWS had four changes worth knowing about. Two of them affect how you design and pay for an SDDC.

**Smaller stretched clusters.** A stretched cluster spreads one vSAN cluster across two Availability Zones, with a witness in a third AZ that breaks ties if the two sides lose contact. Every write goes to both AZs, so if one AZ fails, the VMs restart in the other with no data loss. The catch has always been the entry cost: the floor was six hosts. Now a stretched cluster can scale down to four hosts (two per AZ) or even two (one per AZ), as long as resources allow it. There are exceptions. Clusters running Large management appliances still need six hosts, and clusters with custom CPU core counts set to eight need four. You also can't scale down a cluster that's already close to its resource thresholds.

**HCX 4.11.3 drops WAN optimization.** HCX is the migration tool most people use to move VMs into VMC. The WAN-OPT appliance used to sit in the service mesh and compress and dedupe migration traffic over slower links. It's gone in 4.11.3, which is now the only upgrade target and is supported until October 11, 2027. Before you upgrade, remove WAN-OPT from every service mesh and compute profile, or the upgrade won't go cleanly.

**Better i3 conversion estimates.** i3.metal is the oldest host type on VMC. The updated VMC Sizer now looks at six resource dimensions, and whichever one is tightest sets the host count. Moving to i4i.metal or i3en.metal often needs fewer hosts, because the newer hosts have more cores, memory and storage each. Treat the numbers as a planning estimate. Final counts are checked during the conversion itself.

The fourth change is cosmetic but welcome: a redesigned console at vmc.broadcom.com.

If you've held off on stretched clusters because of the six-host minimum, run the numbers again. And if you're still on i3, the conversion estimate is a quick way to see what moving off it would cost.
