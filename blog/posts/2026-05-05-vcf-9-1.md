Broadcom announced VCF 9.1 on May 5, the first feature release after 9.0. These are the parts I'd look at first.

**Memory tiering grows up.** Memory tiering lets ESX use local NVMe as a second, slower tier of memory. A tiering engine watches which memory pages VMs actually use. Busy ("hot") pages stay in DRAM, and idle ("cold") pages move to NVMe. Most VMs touch only a fraction of their memory at any moment, so a host can run more VMs than its DRAM alone would allow. In 9.1 you can mirror the tier device in software across two NVMe drives, so losing one drive doesn't take memory with it, and there's built-in analysis of the cost savings. It's the feature that makes cluster density on cloud hosts look very different.

**vSAN data reduction on more clusters.** Inline deduplication and compression now work on more cluster types and workload profiles, and deduplication now works with data-at-rest encryption. Less raw capacity per usable terabyte means fewer hosts for storage-bound clusters.

**Live patching.** On hosts with a TPM, many ESX patches can be applied to the running kernel without evacuating the host. Broadcom says this covers up to 80% of patches. For large clusters that's a big cut in maintenance time.

**Ransomware recovery on-prem.** Cyber recovery now works with isolated clean rooms inside VCF, so you can test and recover workloads in a quarantined environment before putting them back.

**Also new:** faster VM and Kubernetes deployment using linked clones, larger fleet and upgrade scale, and native S3-compatible object storage on vSAN as a tech preview.

9.1 is also one of the two VCF 9 versions Amazon EVS added in July, so if you're planning EVS on VCF 9, start here. The 9.1.x line has continued since, with 9.1.1 in September and 9.1.2 in November.
