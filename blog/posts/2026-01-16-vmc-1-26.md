SDDC 1.26 moves VMware Cloud on AWS to vSphere 8.0 Update 3. It's the biggest platform release VMC has had in a while, and it changes how you size storage.

**vSAN ESA.** vSAN has two architectures. The Original Storage Architecture (OSA) splits each host's drives into a cache tier and a capacity tier, organized in disk groups. The Express Storage Architecture (ESA) was built for fast NVMe: there's no cache tier, every drive adds capacity, and compression and snapshots are built into how data is stored. In 1.26, ESA is the default for new i4i.metal SDDCs, but only for SDDCs in a single AZ. Stretched clusters stay on OSA.

The practical difference is RAID-5. On ESA, RAID-5 works from three hosts using a 2+1 layout: two data blocks and one parity block. You can lose a host and keep running, and only a third of the raw space goes to protection. On OSA, three hosts usually means RAID-1 mirroring, which uses half. So a small ESA cluster gets noticeably more usable storage from the same hosts. ESA also always verifies checksums, and the per-host component limit goes from 9,000 to 27,000.

**Bring your own key.** You can now encrypt VMs with keys from your own KMIP-compliant key management system, through vSphere VM Encryption. That covers workload VMs. The VMC control plane still uses AWS KMS for vSAN encryption, managed by Broadcom. If you migrate encrypted VMs with HCX bulk migration, both SDDCs need the same key provider.

**VM hardware version 21.** VMs can have up to 256 disks (64 per NVMe controller across four controllers), up from 60, and NVMe disks can now be used for Windows Server Failover Clustering. The upgrade is one-way and needs the VM powered off, so only do it for VMs that need these limits, and test first.

**VMware Tools 12.5.4** ships with it.

If you're starting a new single-AZ SDDC, ESA is the default and worth it. If you have a security team that wants to hold its own encryption keys, BYOK is the feature they've been asking for.
